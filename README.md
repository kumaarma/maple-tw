# 新楓之谷查詢站（台版 TMS）

跑在本機的查詢站，資料來自 **NEXON Open API** 台版端點
（`https://open.api.nexon.com/maplestorytw/v1`）。兩個功能頁：**排行榜** 與 **角色查詢**。

## 快速開始

雙擊 `start.bat`（或 `python server.py`），瀏覽器會開 <http://127.0.0.1:8787>。
金鑰已存在 `apikey.txt`，可從右上角「金鑰」更換。

換連接埠：`python server.py --port 9000`

## 為什麼需要後端

瀏覽器不能直接打 NEXON API：CORS 會擋，而且金鑰寫在前端 JS 等於公開。
`server.py` 同時送出靜態網頁、代理 `/api/*` 並在伺服器端補上金鑰標頭。

## 金鑰層級 — 會決定你能用什麼

官方把應用程式分兩級，這直接影響本站可用範圍：

| 層級 | 流量 | 角色／裝備／聯盟 | 排行榜、公告 |
|---|---|---|---|
| **開發階段**（`test_` 開頭） | 5 次/秒 · **1,000 次/天** | ✅ 可用 | ❌ 403 拒絕 |
| **正式上線** | 500 次/秒 · 2,000 萬次/天 | ✅ 可用 | ✅ 可用 |

排行榜端點的路徑本身是正確的（若路徑錯會回 `OPENAPI00006`，實際回的是
`OPENAPI00002` 拒絕存取），所以**排行榜功能已經寫好，換成正式金鑰即可直接運作**，
網頁不必改任何一行。

升級方式：<https://openapi.nexon.com> → My Applications → 註冊「正式上線」
應用程式（需填服務網址、說明、用途）→ 取得新金鑰 → 右上角「金鑰」貼上。

## 配額保護

開發階段一天只有 1,000 次，所以做了三層防護：

1. **按需載入** — 其餘分頁點開才抓。以前一次查詢固定燒 21 次。
   目前實測開站查一隻角色是 **10 次**：`lookup()` 6 次（`id`、基本、能力值、
   人氣、武陵、聯盟），總覽分頁再補 7 次（潛能、極限屬性、性向、裝備、
   套裝效果、機器人、寵物）。後四次是把裝備與寵物併進總覽才加的 —— 一天
   1,000 次配額可查的角色數因此從 111 隻降到 76 隻。要換回去的話，把
   `TABS` 第一列的 `'equip'`、`'setEffect'`、`'android'`、`'pet'` 拿掉，
   `renderOverview` 的右欄、套裝效果區塊、`withAndroid()` 與 `petPanel()`
   跟著移除。
2. **磁碟快取** — 官方資料每日凌晨更新，所以快取存活到隔天 01:30，
   存在 `cache.json`，重開伺服器也不會失效。只快取成功的回應，錯誤不快取。
3. **節流與計數** — 每秒最多 4 次上游請求（上限 5）；今日用量顯示在右上角，
   超過 60% 轉黃、85% 轉紅。記錄在 `quota.json`。

金鑰視窗裡有「清空快取」。

## 功能

### 排行榜
綜合（等級／經驗）、聯盟、公會、武陵道場、無限世界塔、成就。
可依世界、職業、公會類型、難度、日期篩選，並支援翻頁。
**點任一列會直接跳到該角色的完整資料** —— 排行榜 → 裝備一氣呵成。

世界名稱會從查詢結果自動累積成下拉建議。

### 角色查詢

| 分頁 | 內容 |
|---|---|
| 總覽 | 等級、職業、公會、經驗條、戰鬥力、全能力值、**裝備欄**（含預設組、星力、卷軸、靈魂、潛能）、套裝效果、極限屬性、潛能能力、性向、武陵 |
| 造型 | 髮型臉型膚色、寵物、機器人、現金裝備 |
| 符文 | 等級、力量、加成、成長進度 |
| 聯盟 | 聯盟等級等階、神器、攻擊隊／佔領／內部效果 |
| HEXA | 六轉進度、HEXA 核心與能力值、V 矩陣 |
| 技能 | 連結技能；各轉職階段可另外點選查詢 |
| 經驗 | 逐日經驗成長長條圖、摘要數字、表格檢視（見下） |
| 原始資料 | 逐端點檢視 JSON、一次抓全部、下載成檔案 |

### 最近查詢

搜尋框下面是查過的角色，卡片式、橫捲一排（15 張往下疊會把搜尋框整個推出
畫面）。每張卡片給頭像、等級／世界／公會、本級經驗百分比與戰鬥力，點卡片
任何位置就重查那隻角色。

**戰鬥力用「億／萬」分段**：`1,025,399,544` 這種千分位讀不出量級，要數逗號
才知道是十億還是一億；`10億2539萬9544` 一眼就看得出來。中段補零到四位是
刻意的 —— 一億又一點戰鬥力寫成「1億1」會被讀成 1 億 1 萬，寫
「1億0000萬0001」才沒有歧義。四位數以下不加單位。

**`MAX` 那行是歷史最高，API 沒有這個欄位**，是本站每次查詢時自己跟舊值比大
存下來的。所以第一次查一定等於現值，那時候不顯示 —— 沒有比較基準時印一次
一樣的數字只是雜訊。

**愛心是收藏。** 收藏的排在前面，而且不會被新查詢擠掉。名額還是總共 15 個
（收藏優先分配），所以 localStorage 不會無限長大。兩組各自再按最後查詢時間
排 —— 不排的話順序會跟著呼叫路徑跑，同一個動作有兩種結果，看起來像隨機。

**分享是複製網址。** 複製出來的是 `?name=角色名`，開站時會讀 `?name=` 與
`?date=` 直接落在那個角色上。查詢成功也會用 `replaceState` 把網址同步成同一
個形式，所以重新整理、加書籤、直接複製網址列都還在同一隻角色（用
`replaceState` 不是 `pushState`：查十個角色不該在瀏覽器裡堆十筆上一頁）。

## 靈魂武器的兩代欄位

改版後的靈魂武器換了一組 API 欄位，兩代會並存在同一件裝備上：

| | 欄位 | 內容 |
|---|---|---|
| 舊 | `soul_name` · `soul_option` | 靈魂名稱與一條選項 |
| 新 | `soul_weapon_grade` · `_level` · `_option` · `_power_increase` | 階級、等級、烙印、共鳴 |

實測有靈魂武器的角色**只填新的那組，`soul_name` 與 `soul_option` 是 `null`**。
只認舊欄位的話整塊會安靜地消失 —— 畫面照樣渲染，只是少了一段，截圖看不出來。
所以 `soulWeapon()` 兩組都看，`soul_weapon_option` 優先、退回 `soul_option`。

**遊戲畫面上有、但 API 不給的**：成長經驗（例如 376/1704）、靈魂的鬥志（技能名）、
各 BOSS 獲得量、靈魂碎片存量。抓不到就不顯示，不自己補一個進度條出來。

## 六轉進度怎麼算

HEXA 分頁最上面會算出「離全滿還有多遠」：核心等級總和 ÷ 滿級總和，分類再各給一條，
接著是**還差多少靈魂艾爾達與碎片**，最後附未滿級核心清單（逐顆列出還要花多少）。

三個要知道的前提：

- **分母是預期核心數，不是回傳到的核心數。** API 只回已經開出來的核心，還沒開的整筆
  不會出現。照回應算的話，「4 個精通核心都滿級」與「只開了 1 個而且滿級」都會算成
  100%。所以寫死目前台版的配置（技能 2、精通 4、強化 4、共用 2，共 12 個，360 級），
  少開的會標成「尚未開啟 N 個」。改版增減核心時改 `app.js` 的 `HEXA_EXPECT`；
  真的抓到比表更多的核心，會改以實際數量當分母，不會算出超過 100%。
- **材料耗量是寫死的表。** 官方 API 只回等級，不回耗量，所以 `HEXA_COST` 存了各類型
  每一級要花的靈魂艾爾達與碎片（來源：MapleStory Wiki 的 HEXA Matrix 頁）。已開啟的
  核心從目前等級往上加，還沒開啟的連開啟費用一起算。抽查對得上兩個獨立來源：技能核心
  29→30 是 20 艾爾達 + 500 碎片，5 轉共用強化核心 0→30 合計 137 / 4,035。
  遇到表裡沒有的核心類型會標明「不含 N 個沒有費用表的核心」，不會悄悄當成 0。
- **「下一步最划算」排的是等級效率，不是傷害效率。** 排出接下來 20 級裡碎片花最少
  的組合，用背包 DP 算 —— **不能**用「每步挑最便宜」的貪心。要注意成本**不是**一路
  遞增：付掉開啟費或每 10 級的尖峰之後，解鎖出來的下一級反而更便宜（強化核心 0→1
  要 75 碎片，1→2 只要 23）。貪心會為了閃尖峰跑去點別顆，結果尖峰照付、後面便宜的
  一段又沒吃到，實測比最佳解貴 6%～13%。列出來的先後只是照「當下最便宜」排給你看，
  總花費跟順序無關，但中途停手的話省下來的不一定最多。至於哪一顆對你的輸出貢獻大，
  要有職業技能係數才算得出來，官方 API 不提供，這份順序不會告訴你那件事。
- **百分比仍是等級的線性比例。** 29→30 比 1→2 貴得多，所以那個百分比會高估後段的
  完成度 —— 要看真正還剩多少，看「還差」那一行的材料數字。
- **台版還沒開放的核心單獨列一塊，不併進進度。** 併進去的話所有人的完成度會無故掉
  一截，可是那不是他們沒練，是遊戲還沒開。所以進度與「還差」都只算現有內容，未開放
  的另外標「台版未開放」並附上開放後的追加需求。

技能核心的起源與昇華除了 0→1 的開啟費用之外每一級都相同，所以共用一張表，開啟費用取
昇華的（起源免費而且人人都有，缺的那個必然是昇華）。

共用核心則相反 —— 索爾雅努斯／赫卡忒是 208 / 6,268，強化 5 轉共用技能的「第三共用
核心」只要 137 / 4,035，差很多，但 API 兩種都回 `hexa_core_type: '共用核心'`，只能靠
名字分（`commonCoreKind()`）。第三共用核心是海外版 v253 才公布的，台版未開放，所以
放在 `HEXA_UPCOMING` 而不是 `HEXA_EXPECT`。`HEXA_COMMON3_SKILL` 另外用職業名對出是
哪個技能（例如凱內西斯 → 異界殘像 VI），對不上就不顯示技能名，其餘照常。

**台版實裝那天要改一行**：把那筆從 `HEXA_UPCOMING` 拿掉，`HEXA_EXPECT.共用核心`
改成 3。已經開出這顆的人本來就會被自動算進分母，但實裝後還沒去開的人不會 —— 那時候
正確的顯示是「尚未開啟 1 個」而不是「台版未開放」。

能力值核心另外算一條等級：三組各自的主屬性 + 兩個副屬性等級加總，滿是 20，共 60。
（實測 `stat_grade` 就是這三個等級的總和，所以只在等級欄位缺漏時才拿它當備援。）
能力值是重骰抽的，花多少碎片沒有定數，所以**不計入**「還差」的材料統計。

## 經驗追蹤怎麼算

API 每天只給一張快照，所以「經驗」分頁是逐日抓 `character/basic` 再自行比對出成長。

**單位是「本級進度的百分比」而不是原始經驗值**，這是刻意的：`character_exp`
是本級累積經驗，不是總經驗，一旦跨等級就無法直接相減。改用

```
成長 = (等級差) + (百分比差) / 100     // 內部以「級份」計算
```

跨級時依然正確。顯示時一律乘 100 標成 %，清單、圖表 y 軸、tooltip、表格
四處同一單位（早期版本這四處混用 % 與級份，圖表還沒標單位）。
跨等級那天成長會超過 100%。原始 EXP 增減只在當日沒升級時才顯示，升級當天標為「（跨等級）」。

- 選 7 / 14 / 30 天，按「載入」；按鈕旁會先告訴你這次要花幾次 API。
- **歷史快照不會再變動，所以抓過的日期永久存在瀏覽器**，之後重看完全免費，
  換天數區間也只補抓缺的那幾天。
- 抓不到資料的日期會記成空值，不會反覆重試浪費配額。
- 這裡刻意不用「失敗時改成不帶 date 重試」那套邏輯 —— 那會把最新資料
  誤植成某個歷史日期，讓整條曲線失真。

圖表為單一數列，資料色 `#cf7418` 已通過亮度帶、彩度下限與底色對比檢查
（網站主色 `#ff9a3c` 亮度 0.776 超出深色模式的 0.48–0.67，不可當資料色）。
升級當天以 ▲ 符號標示而非換色，避免只靠顏色傳達資訊；另附表格檢視。

## 容錯設計

- **日期**（已用真實角色實測）：
  - `date=今天` → 400 `OPENAPI00004`，官方不接受。
  - `date=昨天` → 回傳該日 00:00 的歷史快照。
  - **不帶 `date`** → 回傳比昨天更新的一筆（實測經驗 26.712% vs 昨天的 25.261%）。

  所以角色查詢的日期欄位**預設留空＝取最新**，填日期才是查歷史快照，且上限擋在
  昨天。歷史序列（經驗追蹤）則一律帶明確日期。
  某端點若對日期不買帳，前端會自動改成不帶 `date` 重試一次。
- **欄位**：排行榜表格若遇到與預期不同的欄位名稱，會依實際回應自動組欄位，
  不會整頁空白。角色頁各區塊獨立容錯，壞掉幾個不影響其他區。
- **錯誤**：失敗原因顯示在該分頁，並在「原始資料」下拉標上 ⚠。

## 介面

**裝備沒有獨立分頁，併在總覽裡。** 桌機上屬性面板在左、EQUIPMENT 在右 ——
屬性面板只有 640px 寬，右邊本來整片空著。預設組（目前穿戴／第 1～3 組）
就在 EQUIPMENT 面板內，跟遊戲的 PRESETS 一樣，不用再切分頁。

**裝備格子的位置照遊戲的裝備視窗**，七欄六列，角色圖佔第 3～5 欄的第 1～4 列：

|  | c1 | c2 | c3–c5 | c6 | c7 |
|---|---|---|---|---|---|
| r1 | 戒指1 | 臉飾 | 角色圖 | 帽子 | 披風 |
| r2 | 戒指2 | 眼飾 | ↑ | 上衣 | 手套 |
| r3 | 戒指3 | 耳環 | ↑ | 褲/裙 | 鞋子 |
| r4 | 戒指4 | 墜飾 | ↑ | 肩膀裝飾 | 勳章 |
| r5 | 腰帶 | 墜飾2 | 武器 · 輔助武器 · 徽章 | 機器人 | 機器心臟 |
| r6 | 口袋道具 | — | — | — | 胸章 |

這份對應是照著遊戲畫面逐格核對出來的，**不要從圖示去猜** —— 遊戲的格子沒有
文字標籤。改版新增部位時同樣要開遊戲對一次。欄位名用 API 的原字串（褲子是
`褲/裙`、副武器是 `輔助武器`、肩膀是 `肩膀裝飾`、心臟是 `機器心臟`）。

主視窗放不下的 `寶石`、`輔助特殊技能戒指` 落在「其他」區，圖騰與拼圖各自成區。
沒排進表裡的欄位不會消失，一律進「其他」。

**機器人那一格要另外補。** NEXON 把它放在 `character/android-equipment`，
不塞進 `item_equipment` —— 所以「目前穿戴」的機器人格會空著，但預設組裡有
（預設組是整份快照）。遊戲沒有這種區分，永遠顯示現在穿的、包含機器人，
所以 `withAndroid()` 會在 `item_equipment` 沒有機器人時從那個端點補一件進去。
補的那件只給名稱、圖示與說明 —— 星力、卷軸、潛能等欄位整個不給，**不能給 0**：
詳情彈窗是用 `!== undefined` 決定要不要印那一行的，給 0 會多出一句沒意義的
「卷軸強化 0 次」。

**寵物面板排法照遊戲的 PET 視窗。** 一隻寵物是一個 2×2 區塊：上排是寵物
本體與牠的裝備，中間是名字，下排兩格是自動技能。沒設定的技能格子照樣留著
（遊戲裡是灰色的「PET SKILL」），少畫的話三隻寵物的下排會對不齊。

格子固定 62px 不跟著區塊寬度長大 —— `.eqcell` 有 `aspect-ratio: 1`，用 `1fr`
的話窄螢幕一欄時會撐成 139px 高、裡面只有 30px 的圖，掃描器會判成空白破洞。
遊戲的格子本來也是固定尺寸。

總覽只放圖；技能清單、說明與到期日留在「寵物」分頁 —— 那些遊戲的 PET 視窗
也沒有，所以那個分頁保留著。

**「詳細清單」檢視拿掉了。** 那些數值點格子就看得到，而且詳情彈窗裡拆成
基礎／追加／卷軸／星力四段，比清單細。留著只是同一份資料的較差版本。

**分頁列在手機上是一排橫捲的，不是換行。** 分頁換行會在 375px 擠成
三排、吃掉半個畫面，而且看不出右邊還有幾個。改成單排橫捲之後右緣做淡出
提示，配 scroll-snap 停在分頁邊界；用鍵盤或程式切到看不見的分頁時會自己
捲過去（改 `.tabs` 的 scrollLeft，不用 `scrollIntoView` —— 那個會連整頁
一起捲，畫面會跳）。

**分頁列照 WAI-ARIA 的 tablist 約定做。** 左右鍵換分頁、Home/End 跳頭尾、
roving tabindex 讓整列只佔一個 Tab 停留點 —— 11 個分頁各自可 Tab 的話，
鍵盤使用者要按 11 次才跳得過這一列。

**圖示是 SVG sprite，不是 emoji。** 同一個 emoji 在 Windows／Android／iOS
是三套畫風，大小與基線也各自為政，擺進按鈕裡對不齊。SVG 三個平台一致，
描邊吃 `currentColor`，按鈕變色時圖示自己跟著變。星力的 ★ 是遊戲數值不是
圖示，保留；`<option>` 裡的 ⚠ 也保留 —— 那裡只吃純文字，放不進 SVG。

**焦點看得見。** `input`／`select` 原本設了 `outline: none` 沒補回來，按鈕
更是完全沒有樣式。改用 `:focus-visible`，只在鍵盤操作時出現，滑鼠點擊不會
多一圈框。

**尊重系統的「減少動態效果」。** `prefers-reduced-motion: reduce` 時把轉場與
動畫收掉 —— 這個站的動畫都只是點綴，拿掉不影響功能。

色票沒動：`--muted` 在卡片上是 5.46:1、`--text` 13.42:1，本來就過 4.5:1。
